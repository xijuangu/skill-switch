# skill-switch 用户指南

skill-switch 用一个权威源码库管理 AI 编程工具的 Skill，并把选中的 Skill 部署到 TRAE、Codex、Claude Code、Agents、Gemini CLI 等工具目录。

## 先理解三个概念

- **权威来源**：skill-switch 管理的正式版本，位于 `~/.skill-switch/skills`。只有权威来源可以部署。
- **候选来源**：扫描外部目录或旧工具目录时发现的版本。文件仍归原位置所有，整理成权威来源后才能部署。
- **目标关系**：某个 Skill 与某个工具目录之间的关系。受管部署可由 skill-switch 更新和取消；外部订阅在接管前只读。

## 第一次使用

1. 在“工具”中启用需要管理的工具，确认检测到的目录正确。
2. 打开“技能”，点击“扫描”。
3. 检查发现的 Skill：权威来源可以直接部署；候选来源先“整理”；同名不同内容需要明确选择权威版本。
4. 点击“部署”，选择目标工具。默认模式为 `symlink`。

## 安装 Skill

“安装”支持 GitHub、ZIP 和本地目录。三种方式都会把 Skill 安装到权威源码库；添加本地目录会复制内容，原目录保持不变。

安装成功后，窗口会进入部署步骤。每次部署成功后窗口不会自动关闭，可以继续部署到其他工具，完成后手动关闭。

如果只是想登记并持续扫描一个外部目录，请在“工具 → 发现目录”中登记候选目录，而不是使用“安装”。

## 整理（Consolidation）

候选来源不能直接部署。把选中的候选来源“整理”到权威源码库后，它才成为权威来源，后续部署都从这一份权威内容派生。

- **预览**：整理会写入权威位置、把原候选来源归档、并移除指向旧来源的已知工具条目；可选权威库内的相对父目录（默认根目录），最终目录名始终由技能名决定。填 `..`、绝对路径、软链接逃逸、重复或已占用目标会被拒绝；确认前会重算 hash、路径和占用，计划变化时也会拒绝。
- **批次与撤销**：一次整理是一个完整批次，必须整体成功；任一步骤失败会停止并整批回滚。回滚未能完成时进入待恢复状态并保留现场。整理成功后可以“撤销整理”恢复原候选来源和旧工具条目；原位置被占用时拒绝撤销。
- **版本冲突**：同名不同 hash 的候选进入冲突对话框，按 hash 分版本，可预览 SKILL.md 与文本差异。必须显式选定一个原名权威版本，系统不自动选择或合并；其余版本可“仅归档原版本”或“另存为新 Skill”（新名同时成为身份与目录名）。
- **来源归档区**：整理移除的原候选来源按批次永久保留，可在“恢复”页的“来源归档”标签查看内容、原路径和可恢复状态。整批可恢复；永久清理分两步（预览 → 确认），清理只删除载荷，批次与审计记录仍可查。
- **移动权威 Source**：在不改变身份和内容的前提下，把权威来源移到权威库内的新位置并原子更新受管链接。任一外部订阅仍引用该 Source 时禁止移动；移动可撤销，旧位置被占用或内容已变时安全拒绝。
- **来源恢复**：权威来源缺失或不可读时，该技能的整理、部署、移动等变更被冻结。系统从归档、历史权威版本、copy 部署和用户指定目录收集恢复候选，按内容与最后已知 hash 分类，但不自动提升任何副本；用户选定后恢复到原位置并重新评估所有部署。

整理不自动创建部署；整理完成后请另行把权威来源“部署”到目标工具。

## 部署模式

- **symlink（默认）**：工具目录链接到权威来源，权威内容更新后立即生效。
- **copy**：在工具目录保存独立副本。来源或目标被修改时，应用会显示漂移状态。
- **junction**：Windows 可用的目录链接模式。

平台无法创建链接时，应用不会静默改成 copy，而是显示降级原因并要求确认。

## 批量操作

1. 在“技能”页点击“批量”。
2. 勾选 Skill，或点击“全选当前”。
3. 点击“操作”，选择动作：
   - **部署**：按 Skill × 目标工具选择部署项，默认使用 symlink。
   - **取消部署**：可先筛选某个目标工具，再取消所选关系。
   - **从注册表移除**：逐个安全检查并移除所选 Skill。
4. 执行后，成功项会取消选择；失败项保留，可以处理原因后直接重试。

批量操作不是全有或全无。每一项都有独立结果；“需要确认”或“需要恢复”的项目不会被当作成功。

“工具 → 部署关系”也支持直接勾选关系：

- 受管部署可批量取消部署，或只批量解除登记并保留工具目录内容。
- 外部 Skill 在工具页显示"未管理"或"已登记候选"。在 Skills 页点"扫描"后自动登记为候选来源（不移动文件），整理成权威 Source 后再部署。

## 外部订阅、接管与旧目标

扫描到由其他程序创建的链接时，应用把它登记为“外部订阅”。接管前，skill-switch 不会删除或改写它。

- 要由 skill-switch 管理该关系：在“工具”页点击“接管”。
- 不再跟踪该关系：点击“解除登记”，只删除元数据，不改磁盘内容。
- 如果原工具目录已从工具配置中移除，关系会显示“目标已移除”。这类旧关系不能接管，应核对旧路径后“解除登记”。

“待确认”表示当前关系尚未获得文件变更权限，不等于已经接管。

## 检查更新

在“设置 → 版本与更新”点击“检查更新”。应用只读取 GitHub Latest Release 元数据；发现新版本时会在系统浏览器打开对应 GitHub Release 页面，不会自动下载或安装。没有网络或 GitHub 暂时不可用时，当前版本不受影响。

## 取消部署与从注册表移除

- **取消部署**只移除某个工具上的受管部署，权威来源和其他工具不受影响。
- **从注册表移除**会先检查全部目标关系：
  - 仍有外部订阅或待确认关系时，操作会在创建备份和修改文件之前拒绝。
  - 只有候选来源时，仅移除登记，外部源目录不删除，也不创建无意义备份。
  - 存在权威来源时，先安全取消全部受管部署，再备份并删除权威内容。

如果看到“外部订阅尚未接管”或“待确认”，先去“工具”页接管有效关系，或对无效、已移除目标解除登记。

## 漂移与恢复

- 目标缺失：可“重新部署”。
- copy 来源或目标被修改：按提示确认覆盖方向；双向变化不会自动选择。
- “需要人工恢复”：说明上次文件操作未能完整补偿。请保留现场和备份，不要手动清理标记文件，再根据界面证据选择恢复方案。

备份可在“恢复”页的“备份”标签查看、恢复和删除。恢复到已有路径时，应用会先创建 safety-net 备份。

## 常见问题

### 为什么候选来源不能部署？

候选来源不归 skill-switch 管理。先“整理”到权威源码库，避免部署后原目录移动或删除导致所有工具失效。

### 为什么 symlink 变成 copy？

应用只会在平台能力不支持链接时提出降级，并要求你确认。取消确认不会写入目标。

### 操作失败后为什么没有备份？

预检失败表示尚未开始文件变更，因此不应创建备份。只有应用拥有且准备删除的权威内容才需要备份。

### 卸载 skill-switch 会破坏工具中的 Skill 吗？

copy 部署仍是普通目录；symlink/junction 仍指向 `~/.skill-switch/skills`。卸载应用前不要删除该目录。
