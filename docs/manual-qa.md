# MVP 手工验收清单

## 技能

- 扫描后，技能行显示 source 类型、source 数量和已部署工具；详情中的每个来源明确标记为“权威来源”或“候选来源”。
- Discovery Target 中未受管理、且指向有效 Skill 目录的软链接会登记为只读“外部订阅”；Source 路径必须是 `realpath` 后的权威目录，link path 不得成为 Source。两个 Target 的 alias 指向同一目录时应显示一个 Source、两个外部订阅；接管前不显示重新部署或取消部署，接管时重新校验链接且不改文件，接管后才可独立取消。copy / symlink / junction managed target 均不反向登记为 Source，broken link 与文件 link 被安全跳过且不中断整次扫描。
- 展开 Source 后，“发现时间”按当前系统本地时区显示，不直接展示 UTC `Z` 字符串。
- “安装”默认打开 GitHub 安装；“添加本地”直接打开本地目录页。GitHub、ZIP、本地目录均写入权威源码库；本地安装复制内容且不修改原目录。
- 安装成功后进入部署步骤；每次部署成功后弹窗保持打开，可继续选择其他工具，直到用户主动关闭。
- “设置 → 权威源码库”显示固定的 `~/.skill-switch/skills`，不提供任意路径修改入口。
- 在“工具 → 发现目录”登记一个包含多层目录和多个 `SKILL.md` 的 Root；系统递归发现每个真实 Skill 为 Candidate Source，但不向任何工具自动写入文件。
- 对同一个 Root 重新扫描可发现新增 Skill；解除登记只删除注册元数据，Root 和 Skill 文件仍保留在磁盘。
- 从 Root 发现两个 Skill 后，只部署其中一个到选定 Discovery Target；未选择的 Skill 不应出现在该工具，取消单个订阅不删除 Source 或其他 Target 的订阅。
- 多 source 冲突时，部署和查看 SKILL.md 都要求选择具体 source。
- 多版本冲突时，详情列来源按 hash 分组渲染（版本 A / 版本 B 标题 + 来源数 + hash 短码），单版本保持平铺。
- 部署弹窗在冲突 skill 上显示当前所选 Source 所属版本组（组内来源数、hash 短码）与其他版本数量。
- 切换筛选时左侧 nav 固定不动；Skills 页只有列表区与详情区两个独立滚动条，无嵌套或页面整体滚动。

## 部署与工具

- 多路径工具的部署框以稳定 Discovery Target 分项展示，不把路径作为 mutation 参数回传。
- 工具页顶部汇总所有外部订阅；“一键接管”先按工具展示完整预览，确认后逐条重新校验。有效项变为受管部署，失效项保持外部订阅并显示原因；部分成功后可“重试剩余”，整个过程不重建或修改链接。单条“接管”仍可独立使用。
- external 内容、已修改目标和模式降级在同一个中文确认框中聚合展示；取消后磁盘不变。
- 请求 symlink/junction 但只能使用 copy 时必须确认，不能静默降级。
- 新建单个部署与批量部署均默认选择 symlink，用户仍可显式切换 copy。
- Skills 页进入批量模式后可选择多个 Skill：批量部署按 Skill × Discovery Target 选择；批量取消部署可按目标工具筛选；批量从注册表移除逐项显示结果。成功项取消选择，失败项保留并可重试。
- 已从工具配置移除的旧 Discovery Target 显示“目标已移除”，只提供“解除登记”；解除仅删除元数据，不触碰旧路径内容。
- 从注册表移除在任何备份或文件变更前预检全部关系；存在外部订阅/待确认关系时拒绝且不产生备份，只有候选来源时仅移除登记并保留外部目录。
- 同一 Discovery Target 快速重复操作时后到请求提示“目标正在执行其他部署操作”，其他 Target 不受影响。
- 模拟中断遗留 marker/staging/rollback 时显示“需要人工恢复”，不自动选择旧内容或新内容。
- 删除目标后点击“重新部署”会恢复目标。
- 修改 copy 目标、替换链接、删除 Source 时显示对应异常状态；Skills 与 Tools 页结果一致。
- 禁用工具仍显示在“工具配置”区域，可在同一位置重新启用；禁用后不参与扫描和新部署。

## 权威库整理生命周期（#82–#92）

### 准备候选数据

- 「工具 → 发现目录」登记一个含多个 `SKILL.md` 的目录，回「技能」页点顶部「扫描」。权威库外发现的来源在详情中标记为「候选来源」，库内为「权威来源」（#82）。
- 「设置 → 权威源码库」固定显示 `~/.skill-switch/skills`，无任意改路径入口（#82）。

### 整理与撤销（#84 #86）

- 选中技能，详情区点「整理」：预览显示写入权威位置、原来源归档、移除已知旧工具条目，可选权威库内相对父目录（默认根目录），最终目录名始终由技能名决定。
- 填 `..`、绝对路径、软链接逃逸、重复或已占用目标应被拒绝；确认前重算 hash/路径/占用，计划变化时拒绝。
- 执行成功后只剩一个权威来源，且不自动创建部署；点「撤销整理」恢复原候选来源与旧工具条目，路径被占用时拒绝。
- 多技能可在一个批次共享单次预览与确认；任一阶段失败整批回滚，补偿失败进入待恢复并保留现场（#85）。

### 版本冲突与权威替换（#87 #89）

- 同名不同 hash 的候选进入冲突对话框：按 hash 分版本，可预览 SKILL.md 与文本差异；必须显式选定一个原名权威版本，系统不自动选或合并。
- 其余版本可「仅归档原版本」或「另存为新 Skill」；另存的新名成为身份与目录名，更新权威副本 frontmatter，不改动归档原件，名称冲突/非法名/未解决冲突阻止执行。
- 已有权威版本可作为一个版本参与替换：替换保持 Canonical Placement 不变并归档旧权威内容；copy 部署按 source-only/target-only/双向分别处置，双向变化进入冲突不自动选方向（#89）。

### 移动权威 Source（#90）

- 详情区点「移动权威 Source」，只选新相对父目录，技能身份与内容不变；预览列出新旧位置和受影响部署。
- 任一外部订阅仍引用该 Source 时阻止移动（须先接管或移除外部链接）。
- 点「撤销移动」回到旧位置并恢复链接；旧位置被占用、内容已变或出现新外部订阅时安全拒绝。

### 来源归档（#88）

- 「恢复 → 来源归档」按整理批次显示内容、占用空间、原路径和可恢复状态；归档默认永久保留，无自动过期或扫描清理。
- 已完成批次可「整批恢复」权威内容、原候选来源和旧工具条目；任一原路径被占用时在写入前拒绝。
- 永久清理分两步：先「预览清理」再「确认永久清理」；清理只删除载荷，批次与审计记录仍可查，已清理批次明确拒绝再恢复（文案为「永久清理」，非「永久删除」）。

### 部署资格与来源恢复（#91 #92）

- 候选来源技能不能直接部署，deploy/confirm/redeploy 三入口均拦截并提示需先整理成权威 Source（#92）。
- 权威 Source 缺失或不可读时，该技能的整理/部署/移动等变更被冻结；系统从归档、历史权威版本、copy 部署和用户指定目录收集恢复候选，不自动提升任何副本，用户选定后恢复到原 Canonical Placement 并重新评估所有部署（#91）。

### 全局一键接管（#83）

- 「工具」页顶部汇总全局外部订阅数量（不受展开/筛选影响），点「一键接管外部订阅」按工具分组预览后「确认接管全部」。
- 逐条按语义 ID 重新校验：有效项转受管部署，失效项保持外部订阅并显示原因；部分成功后可「重试剩余」，单条「接管」仍可用；全程不重建或修改文件与链接。

## 备份

- 恢复已有目标前创建 safety-net。
- 保留数设为 1 时仍能完成恢复。
- 删除和恢复只作用于列表中的备份。

## 构建

- `npm run verify` 通过。
- `npm run dev` 能启动应用。
- 当前平台的 `npm run package:*` 能生成安装产物。
